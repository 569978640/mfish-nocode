## 1. 系统概述

### 1.1 项目简介

摸鱼低代码平台是一款致力于**让开发像摸鱼一样轻松**的低代码/无代码平台。平台旨在打破技术门槛，让程序员和非程序员都能快速构建业务系统，提升效率，释放创造力。

### 1.2 核心目标

- **加速开发效率**：通过低代码/无代码方式，快速生成业务代码和API接口
- **统一认证授权**：基于OAuth2的统一身份认证和权限管理
- **简化运维管理**：提供完善的后台管理和监控功能
- **支持二次开发**：提供完整的二次开发指南和代码生成能力

### 1.3 系统特性

| 特性类别      | 具体特性                           |
| --------- | ------------------------------ |
| **架构特性**  | 单体+微服务一体化架构、低代码+无代码统一平台、权限解耦设计 |
| **认证特性**  | OAuth2统一认证、多登录方式支持、登录互斥控制、单点登录 |
| **权限特性**  | 菜单/按钮/角色权限、数据权限控制、租户隔离         |
| **数据源特性** | 多数据源支持、动态配置、可视化API配置           |

### 1.4 适用场景

- 企业内部系统搭建（ERP、CRM、OA等）
- 快速原型设计与验证
- 数据展示看板等轻应用开发
- 快速集成与API开放

### 3.2 网关层设计

网关是系统的统一入口，采用Spring Cloud Gateway实现：

| 过滤器   | 类名               | 功能说明                      | 配置参数                 |
| ----- | ---------------- | ------------------------- | -------------------- |
| 请求缓存  | CacheFilter      | 缓存POST/PUT请求body，解决重复读取问题 | -                    |
| 验证码校验 | CheckCodeFilter  | 防止暴力登录，支持数学验证码            | gatewayCheckCaptcha  |
| XSS防护 | XssFilter        | 过滤恶意脚本攻击                  | security.xss.enabled |
| 限流熔断  | RateLimitHandler | 基于Sentinel的流量控制           | sentinel配置           |

## 4. 接口设计规范

### 4.2 请求格式规范

#### 4.2.1 请求头规范

| 头信息           | 必须 | 说明               | 示例                                             |
| ------------- | -- | ---------------- | ---------------------------------------------- |
| Content-Type  | 是  | application/json | application/json                               |
| Authorization | 是  | Bearer Token     | Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... |
| X-Client-Id   | 否  | 客户端标识            | mf-web                                         |
| X-Request-Id  | 否  | 请求追踪ID           | uuid                                           |

#### 4.2.2 请求参数规范

**路径参数**：用于唯一标识资源

```
GET /sys/user/{id}
```

**查询参数**：用于过滤、分页、排序

```
GET /sys/user?pageNum=1&pageSize=10&status=1
```

**请求体**：用于创建、更新资源

```json
{
  "username": "admin",
  "password": "!QAZ2wsx",
  "status": 1
}
```

### 6.1 认证授权流程

#### 6.1.1 密码登录流程

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  前端    │     │   网关   │     │  认证服务 │     │  Redis   │
└────┬─────┘     └────┬─────┘     └────┬─────┘     └────┬─────┘
     │                │                │                │
     │ 1.登录请求      │                │                │
     │───────────────>│                │                │
     │                │ 2.验证码校验    │                │
     │                │───────────────>│                │
     │                │                │ 3.校验验证码    │
     │                │                │───────────────>│
     │                │                │<───────────────│
     │                │ 4.验证结果      │                │
     │                │<───────────────│                │
     │                │                │ 5.验证账号密码  │
     │                │                │───────────────>│
     │                │                │<───────────────│
     │ 6.返回Token    │                │                │
     │<───────────────│                │                │
```

#### 6.1.2 OAuth2授权码流程

1. 用户访问受保护资源
2. 未认证则跳转授权页面
3. 用户确认授权
4. 授权服务生成code返回
5. 前端用code换取access\_token
6. 携带access\_token访问资源

### 6.2 权限校验流程

#### 6.2.1 请求权限校验链

```
请求 → 网关校验 → Token校验 → 权限注解校验 → 数据权限校验 → 业务处理
```

**各环节说明**：

| 环节      | 组件                   | 说明         |
| ------- | -------------------- | ---------- |
| 网关校验    | CheckCodeFilter      | 验证码校验      |
| Token校验 | AuthFilter           | Token有效性校验 |
| 权限注解    | @RequiresPermissions | 按钮权限校验     |
| 数据权限    | @DataScope           | 数据范围校验     |

#### 6.2.2 权限注解使用

**单条件权限**：

```java
@RequiresPermissions("sys:user:query")
```

**多条件权限(OR)**：

```java
@RequiresPermissions(value = {"sys:user:add", "sys:user:edit"}, logical = Logical.OR)
```

### 7.2 全局异常处理

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MyRuntimeException.class)
    public Result<Void> handleMyRuntimeException(MyRuntimeException e) {
        log.error("业务异常: {}", e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldError().getDefaultMessage();
        return Result.fail(400, message);
    }

    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.fail(500, "系统异常，请稍后重试");
    }
}

## 14. 多数据库架构设计

### 14.1 架构概述

mfish-nocode PLM系统采用**多数据库混合架构**，支持MySQL、PostgreSQL和图数据库（NebulaGraph）三种数据库类型，实现业务数据分库存储和复杂关系查询。

#### 14.1.1 设计原则

| 原则   | 说明                           |
| ---- | ---------------------------- |
| 职责分离 | 关系库存主数据，图库存关系拓扑              |
| 事件驱动 | RocketMQ异步同步，保证事务性能          |
| 最终一致 | 图库允许短暂不一致，以性能换可用性            |
| 配置驱动 | 单节点/集群模式通过配置切换               |
| 混合查询 | 图库负责路径和边业务属性查询，关系库负责节点业务属性查询 |

#### 14.1.2 数据库选型

| 数据库             | 用途      | 存储内容                         |
| --------------- | ------- | ---------------------------- |
| **MySQL**       | 系统配置数据  | OAuth认证、系统管理、工作流、调度等基础数据     |
| **PostgreSQL**  | PLM业务数据 | Product、Part、Document等PLM主数据 |
| **NebulaGraph** | 图关系数据   | 节点关系拓扑、边属性、BOM层级关系           |

### 14.2 模块职责划分

│  mf-plm │ ──── │  Feign     │ ──── │  其它模块 (OAuth/Sys/Workflow等)   │
│        │      │  接口调用   │      │  MySQL 各自数据库                    │
└─────────┘      └─────────────┘      └─────────────────────────────────────┘
```

### 14.5 多数据源使用规范

#### 14.5.1 数据源注解说明

| 注解        | 说明   | 使用场景               |
| --------- | ---- | ------------------ |
| `@Master` | 主库注解 | 写操作、默认读操作          |
| `@Slave`  | 从库注解 | 读操作、从MySQL读OAuth数据 |

#### 14.5.2 使用示例

```java
// PLM业务Service示例
public class ProductServiceImpl {
    
    @Autowired
    private ProductMapper productMapper;  // 使用@Master，默认PostgreSQL
    
    /**
     * 创建产品 - 写操作
     * 使用@Master注解确保写操作走PostgreSQL主库
     */
    @Master
    @Transactional(rollbackFor = Exception.class)
    public void createProduct(Product product) {
        // 1. 写入PostgreSQL
        productMapper.insert(product);
        
        // 2. 发送MQ消息到plm-graph-sync topic
        rocketMQTemplate.convertAndSend("plm-graph-sync", buildSyncEvent(product));
    }
}

// Graph服务中读取OAuth数据示例
public class GraphSyncService {
    
    @Slave
    public List<SsoOrg> querySsoOrgList() {
        return ssoOrgMapper.selectList(null);
    }
}
```

**问题**：Expression #2 of SELECT list is not in GROUP BY clause

**解决**：修改MySQL配置文件，去除only\_full\_group\_by

sql_mode=NO_ENGINE_SUBSTITUTION,STRICT_TRANS_TABLES
